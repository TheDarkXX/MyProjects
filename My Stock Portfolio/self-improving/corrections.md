# Corrections & Mistakes

- **2026-09-02 (Database Schema Mismatch):** When restoring legacy components, ensure foreign key checks use `portfolio_id` (matching SQLite schema) rather than camelCase `portfolioId`.
- **2026-09-02 (Historical Cache Boundary Check):** In `server/routes/historical.js`, checking `cached.length > 0` caused short cache ranges (e.g. 6M from Dashboard) to block larger ranges (e.g. 1Y from Performance). Always ensure `cached[0].date <= from` before declaring cache hit.
- **2026-09-02 (Deployment & PM2):** `My Stock Portfolio` is a hybrid app hosted on VPS `185.250.38.247`. Frontend is deployed via `scp dist/*` to `/root/stock-portfolio/dist/`. Backend is deployed to `/root/stock-portfolio/server/` and managed under PM2 process `stock-api`. Always run `pm2 save` after starting services.
- **2026-09-04 (ReferenceError in Object Shorthand & ErrorBoundary):** In `SmartRebalancePage.tsx`, declaring `const currVal = ...` while returning object shorthand `{ currentVal }` caused a runtime `ReferenceError: currentVal is not defined` when calculating deficits with live holdings. Always ensure object shorthand variables match declarations exactly. Wrap all lazy-loaded root modules in an `ErrorBoundary` in `App.tsx` to prevent component crashes from turning the entire app into a black screen.
- **2026-09-04 (SQLite Database Overwrite & WAL Desync):** NEVER copy local development database `stock.db` to production VPS without verification. The production database contains authentic transaction history, and overwriting `stock.db` directly while PM2 is running and SQLite WAL mode is active causes `SQLITE_CORRUPT: database disk image is malformed` and wipes historical transactions. Always stop PM2 first, verify row counts, checkpoint WAL with `PRAGMA wal_checkpoint(TRUNCATE)`, and maintain automatic pre-deploy backups.
- **2026-09-10 (Lightweight Charts v5 Multi-Pane Sizing & Splitter Drag):** In Lightweight Charts v5, calling `setHeight` sequentially on multiple sub-panes steals height from earlier panes and clamps at `MIN_PANE_HEIGHT = 30px`. To dynamically collapse or expand sub-panes, synchronously set `pane.setStretchFactor(factor)` on all panes simultaneously (with Pane 0 absorbing the leftover height). Never listen unconditionally to `window.mouseup` to save heights, as arbitrary clicks overwrite stored heights with transient collapsed values (< 80px). Always use an `isDraggingSplitter` guard and enforce an 80px minimum floor for expanded panes.
- **2026-09-10 (Lightweight Charts v5 PaneSeparator Deadlock with Collapsed Panes):** Lightweight Charts default `PaneSeparator` strictly trades stretch factor only between its immediate adjacent `topPane` and `bottomPane`. When P1 is collapsed (28px <= `minPaneStretch` 30px), dragging the separator above P2 (Separator 1) to make P2 taller is mathematically deadlocked because P1 cannot shrink below 30px. To fix, capture `pointerdown/mousedown` on the separator above P2 when P1 is collapsed, prevent default/stop propagation to bypass library clamp, and directly stretch P2 against Pane 0 (Main Chart) while keeping P1 pinned at 28px.
