# VVE v13 Upgrade & Pipeline Audit

## 📌 Context (Compiled Truth)
This document captures the V13 major upgrade of the Viral VDO Editing (VVE) pipeline. 
The upgrade focuses on intelligent editorial decisions, configurable style presets, robust error handling, testing, and modernizing the scene generation to support unified video prompts.

**Key Achievements:**
1. **AI Editorial Subagent (`02b-editorial-agent.py`)**: Uses an LLM to analyze the transcript and make rough cut decisions, B-Roll recommendations, SFX placements, and identify turning points. The pipeline now calls this script. It includes graceful error handling if OpenAI is not installed or API keys are missing.
2. **JSON Preset System**: Created `presets/` folder (`anim_pop.json`, `trans_minnie.json`, `style_hormozi.json`) and added a `load_preset()` function in `config_loader.py` to allow dynamic styling based on channel configurations.
3. **SRT Presets**: `03-word-segment.py` now supports predefined parsing rules (`drb`, `hormozi`, `flow`, `classic`) based on the yaml configuration, enhancing subtitle output formatting.
4. **Golden Tests**: Introduced `golden_tests/run_golden_test.py` to enable regression testing against a known "golden" test case (`doctorbank_v1`), verifying pipeline stability without visual inspection of every run.
5. **Unified Video Prompts**: Evolved the scene generation prompt (`doctorbank_masterprompt.yaml`). Created `doctorbank_broll_text2video.yaml` to unify image and motion prompts into a single video prompt. Adapted `05-scene-generator.py` to read the `prompt_mode` (`"video"` or `"image"`) from the yaml channel config and output the TSV appropriately.
6. **Robust Bug Fixes**:
   - Fixed pipeline arguments mismatch where older scripts failed.
   - Fixed `preset` variable scope in `03-word-segment.py`.
   - Fixed transcript filename matching (`*.transcript.json`) in `02b-editorial-agent.py`.

*Note: Highlight and text styles are deliberately kept as Direct JSON manipulation, as the free CapCut CLI does not handle these more efficiently than direct byte-offset math.*

## 1. 🎯 TikTok Keyword Highlight — เขา vs เรา

### วิธีของ cutcli-cookbook (native CLI)
```bash
cutcli captions add <draftId> \
  --data '[
    {"text":"วันนี้จะสอนเรื่อง วิตามิน",
     "start":0, "end":3000000,
     "keyword":"วิตามิน",
     "keywordColor":"#FFD600",
     "inAnimation":"向上滑入",
     "inAnimationDuration":300000}
  ]' \
  --border-color "#000000" \
  --border-width 1
```

**ข้อดี:**
- ✅ **Native** — CLI จัดการ UTF-16 byte offset ให้ทั้งหมดเบื้องหลัง
- ✅ **ง่ายมาก** — แค่ระบุ `keyword` + `keywordColor` จบ
- ✅ **Animation ติดมาด้วย** — `inAnimation`, `loopAnimation` (หัวใจเต้น, slide-up)
- ✅ **Multiple keywords** — ใช้ `|` คั่น เช่น `"keyword":"วิตามิน|แคลเซียม"`

### วิธีของเรา (Direct JSON — 08b-capcut-auto-style.py)
```python
# คำนวณ UTF-16 byte offset ด้วยมือ
pre_text = raw_text[:idx]
start_byte = len(pre_text.encode('utf-16-le'))
end_byte = start_byte + len(match_text.encode('utf-16-le'))

# สร้าง style range
hl_style['range'] = [start_byte // 2, end_byte // 2]
hl_style['fill'] = {"content": {"solid": {"color": hl_rgb}}}
```

**ข้อเสีย:**
- ❌ ต้องคำนวณ UTF-16 offset เอง (เสี่ยง bug กับภาษาไทย)
- ❌ ไม่มี animation ติดมา
- ❌ Code ซับซ้อน (20+ บรรทัด vs 1 command)

### 🏆 สรุป: **ของเขา native กว่าจริง!**

> [!IMPORTANT]
> **แนะนำ:** ย้ายไปใช้ `cutcli captions add` หรือ `capcut text-ranges` แทน — ปลอดภัยกว่ามาก โดยเฉพาะภาษาไทยที่ UTF-16 encoding ซับซ้อน

**แนวคิด:** เก็บ "ตัวอย่างผลลัพธ์ที่ถูกต้อง" ไว้ เพื่อเทียบกับผลลัพธ์ใหม่ทุกครั้ง

├── doctorbank_v1/
│   ├── input/
│   │   ├── raw_video.mp4          ← วิดีโอต้นฉบับ

- 🛡️ ทุกครั้งที่แก้โค้ด ไม่ต้องกลัวว่าจะพังของเดิม

## 3. 🤖 Editorial Subagent — คืออะไร

**แนวคิด:** แทนที่จะเขียนกฎตายตัว (ตัดเสียงเงียบ > 0.5s) → **ให้ AI ตัดสินใจ** ว่าควรตัด/เก็บ/เร่งส่วนไหน

### Flow ปัจจุบัน (VVE)
```
Raw Video → Transcript → masterPrompt (กฎตายตัว) → Scene Table → Footage Assembly
                                 ↑
                        กฎ: "ตัดตาม subtitle timing"
                        กฎ: "B-Roll ทุก 5-8 วินาที"
```

### Flow ที่มี Editorial Subagent (BizDrive)
```
Raw Video → Transcript → AI Editorial Agent → Rough Cut Decisions
                              ↑
                    AI วิเคราะห์:
                    - "ตรงนี้พูดซ้ำ → ตัดออก"
                    - "ตรงนี้พูดเร็วดีแล้ว → เก็บ"
                    - "ตรงนี้หยุดนาน → เร่ง 1.3x"
                    - "ตรงนี้เปลี่ยนหัวข้อ → ใส่ B-Roll"
                    - "ตรงนี้ climax → เปลี่ยน BGM stage"
```

**ต่างจากของเราอย่างไร:**

| | VVE ตอนนี้ | + Editorial Subagent |
|:---|:---|:---|
| **ตัดเสียงเงียบ** | Rule-based (threshold) | AI วิเคราะห์ว่า pause นั้นจงใจหรือเปล่า |
| **วาง B-Roll** | ตามเวลา (ทุก 5-8 วิ) | ตามเนื้อหา ("พูดถึง X → ใส่ภาพ X") |
| **เปลี่ยน BGM** | ตาม turning point ตายตัว | AI หาจุด climax จริงๆ |
| **ตัด filler** | ไม่มี | AI ตัด "เอ่อ", "อืม", "จริงๆ แล้ว" |
| **Speed ramp** | ไม่มี | AI เร่งส่วนที่ช้าเกินไป |

**ระดับความยาก:** 🔴 ยาก — ต้องใช้ LLM วิเคราะห์ transcript + ออกแบบ prompt ดีๆ

## 4. 📦 JSON Templates — คืออะไร

ของ cutcli-cookbook มี `templates/` ที่เก็บ JSON snippet สำเร็จรูป:

```json
// templates/caption-style-tiktok.json
{
  "fontSize": 9,
  "color": "#FFFFFF",
  "borderColor": "#000000",
  "borderWidth": 1,
  "inAnimation": "向上滑入",
  "inAnimationDuration": 300000,
  "transform_y": -0.55,
  "bold": true
}
```

```json
// templates/caption-style-hormozi.json
{
  "fontSize": 15,
  "color": "#FFD600",
  "borderColor": "#000000",
  "borderWidth": 2,
  "inAnimation": "缩放",
  "bold": true,
  "transform_y": 0.0

```

**แนวคิด:** แทนที่จะ hardcode สไตล์ในโค้ด → เก็บเป็น JSON files → เลือกใช้ตาม config

**ของเราเทียบเท่า:** เราใช้ YAML config (`channels/doctorbank.yaml`) ทำหน้าที่เดียวกันอยู่แล้ว แต่ cutcli-cookbook เก็บเป็น "template library" ที่ mix & match ได้อิสระกว่า — เช่นช่องหมอใช้ `caption-style-flow` + `animation-fade-up` ช่องอื่นใช้ `caption-style-hormozi` + `animation-zoom`

> [!TIP]
> **สิ่งที่เอามาได้:** เก็บ animation/effect presets แยกเป็นไฟล์ JSON → YAML config เลือก preset ที่จะใช้ แทนที่จะ hardcode ค่าทุกอย่างใน YAML

### 3. `07-sfx-placer.py` Index Bug — `words[idx]` ไม่ใช่ word ที่ตรงกับ keyword

[07-sfx-placer.py L77](file:///c:/My%20Claw/MyProjects/Viral%20VDO%20Editing%20(VVE)/scripts/07-sfx-placer.py#L77):
```python
idx = full_text.find(kw, start_idx)
sfx_start = max(0, words[idx]["start"] - peak_offset_sec)
```

`full_text` คือ **ข้อความต่อกันของทุก word** (เช่น `"ไตแคลเซียมกระดูก..."`) และ `idx` คือ **character index** ของ `full_text` แต่ `words[idx]` คือ **word object ตัวที่ idx** — ไม่ใช่ตัวเดียวกัน! ถ้า `full_text` มี 500 ตัวอักษร แต่มี 50 words → `words[200]` จะเป็น `IndexError`
