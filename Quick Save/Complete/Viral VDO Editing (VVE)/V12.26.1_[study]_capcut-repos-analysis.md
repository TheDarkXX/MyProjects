# 🔬 Dev Proposal Review — VVE Competitor / Tool Analysis

## 📌 Context (Compiled Truth)
- User requested analysis of 3 external repos automating CapCut (pyCapCut, video-autopilot-kit, capcut-mcp-server).
- **pyCapCut**: Good for Template Mode and tracking JSON schema changes. We will adopt the Template Mode concept and use pyCapCut repository as a reference for schema updates (Mixed Strategy).
- **video-autopilot-kit**: 4-level mute is for muting actual B-roll audio (not relevant as we use AI images). 7-file sync is overkill for Windows (2 files is enough, but note `template-2.tmp` for CapCut 8.8.0+). QA checks are largely irrelevant due to our pipeline's strictness.
- **capcut-mcp-server**: Wrong stack. Good idea on typography parametrization, but not urgently needed as we only operate one channel (DoctorBank).
- **Conclusion**: VVE's custom JSON injection pipeline is highly robust. Adopt only Template Mode + Mixed Schema Strategy.

## 1️⃣ pyCapCut — `GuanYixuan/pyCapCut`

**Source:** https://github.com/GuanYixuan/pyCapCut
**Language:** Python | **License:** Not specified (sister project pyJianYingDraft = MIT)
**Stars:** ⭐ ใหม่ (migrating from pyJianYingDraft 1.2k+ stars)

### 💡 Core Concept — คืออะไร ดีอย่างไร

pyCapCut คือ **Python library** ที่สร้าง/แก้ไขไฟล์ `draft_content.json` ของ CapCut **โดยตรง** — เหมือนที่ VVE ทำอยู่ใน `capcut_editor.py` แต่ข้อดีที่ต่างจาก VVE คือ:

1. **เป็น library (`pip install pycapcut`)** — VVE เขียน JSON manipulation เองทุกบรรทัด ถ้า CapCut เปลี่ยน schema ต้องตามแก้เอง, pyCapCut มี community ดูแล schema ให้
2. **API level สูงกว่า** — แทนที่จะ `seg['target_timerange'] = {"start": ..., "duration": ...}` แบบ VVE, pyCapCut ใช้ `trange("0s", "5s")` อ่านง่ายกว่ามาก
3. **มี Template Mode** — โหลด draft จริง แล้ว duplicate ได้ (ตอบข้อถัดไป)
4. **มี Effect/Sticker/Bubble system** — ใส่ 花字, sticker, animation by `resource_id` ได้ ซึ่ง VVE ทำไม่ได้

> **สรุปง่ายๆ:** VVE เขียน "ภาษา JSON ดิบ" คุยกับ CapCut → pyCapCut เขียน "ภาษา Python สูง" แล้วมันแปลงเป็น JSON ให้ ลดโอกาสผิดพลาด + maintain ง่ายกว่า

### 🎛️ Template Mode — เซต config มาหมดแล้วใช่ไหม? เช็ค parameter ได้ไหม?

**ใช่ครับ concept มันคือ:**

```
1. มึงเปิด CapCut ตั้งค่ามือจนสวย (font, color, transition, position ทุกอย่าง)
2. pyCapCut โหลดไฟล์ draft_content.json ของ project นั้นเข้ามา
3. มัน duplicate ทั้ง project → สร้าง copy ใหม่
4. มึงแค่ swap เฉพาะ "เนื้อหา" (video file, audio file, text) — styling ทั้งหมดคงอยู่
```

**เทียบกับ VVE ที่ทำอยู่:**
- VVE ใช้ `TEMPLATE_PROJECT` ใน `capcut_editor.py` (line 17) → `load_templates()` → clone segment/material templates
- pyCapCut ทำเรื่องเดียวกัน **แต่ครอบคลุมกว่า**: มัน clone **ทั้ง project** ไม่ใช่แค่ segment template

**เช็ค parameter ได้ไหม?** ได้ — ใช้ `inspect_material()`:
```python
script = draft_folder.load_template("Perfect Mark Draft")
script.inspect_material()
# Output: ดึง resource_id ของ sticker, bubble, 花字, transition ทั้งหมดออกมา
```

**สิ่งที่ต้องเช็คก่อน adopt:**
- [x] pyCapCut support CapCut version ที่เราใช้อยู่ไหม (CapCut มี version หลายตัว) ➔ **Support** (สามารถโหลด Draft ปัจจุบันได้ปกติ)
- [x] `inspect_material()` ดึง `vocal_beautifys`, `beauty_face_auto_preset`, `noise_reduction` ออกมาได้ไหม (พวกนี้ VVE ต้องเขียน JSON ตรง) ➔ **ดึงไม่ได้** (ฟังก์ชันนี้ไม่ได้อ่าน property เชิงลึกพวกนี้ออกมาให้)
- [x] Template mode preserve ค่า Y position subtitle (-0.364583) ไหม ➔ **Preserve ได้ 100%** (เพราะ Template mode ของ pyCapCut คือการ Duplicate Folder และ draft_content.json ทั้งก้อน)

## 2️⃣ video-autopilot-kit — `Hao0321/video-autopilot-kit`

**Language:** Python | **License:** Not specified

### 🔍 4-Level Silence — ทำงานยังไง ต่างจาก VAD ยังไง

> [!IMPORTANT]
> **4-Level Silence ไม่ใช่ silence detection เลย — มันคือ "4 จุดที่ต้อง mute พร้อมกัน" เพื่อป้องกัน audio leak ตอน export**

จากที่กูขุด source code `mute.py` มาจริง มันคือบทเรียนจากบั๊กของ CapCut:

**ปัญหา:** CapCut มีบั๊กว่า ถึงจะตั้ง `volume=0` บน segment แล้ว **เสียงยังรั่วออกมาตอน export ได้** (เช่น เสียง original ของ B-Roll clip)

**4-Level Mute Solution:**
```
ต้อง mute 4 จุดพร้อมกันจึงจะการันตี 100% ว่าเงียบ:
1. material.has_audio = false       ← บอก material ว่าไม่มีเสียง
2. material.has_sound_separated = true  ← บอกว่าแยกเสียงแล้ว
3. segment.volume = 0.0             ← volume = 0
4. segment.last_nonzero_volume = 0.0 ← volume สุดท้ายก่อน mute ก็ = 0
```

**Fallback:** ถ้า 4-level mute ยังรั่ว → ใช้ ffmpeg `force_mix_bgm` replace audio track ทั้งหมดเลย

**ต่างจาก VAD ยังไง:**

| | VVE VAD (Timebolt + vad_extractor) | 4-Level Mute (video-autopilot-kit) |
|--|---|---|
| **จุดประสงค์** | **ตัดช่วงเงียบออก** จาก timeline (ย่อเวลา) | **ปิดเสียง B-Roll** ไม่ให้รั่ว (ไม่ตัดอะไร) |
| **Engine** | Timebolt (external) + Python VAD | JSON field manipulation 4 จุด |
| **ผลลัพธ์** | Video สั้นลง (ตัด silence gap ออก) | Video เท่าเดิม แต่ B-Roll เงียบ 100% |
| **ใช้เมื่อไหร่** | ขั้นตอนแรก (ก่อน subtitle) | ขั้นตอนสุดท้าย (หลัง inject B-Roll) |

> **สรุป:** มันคนละเรื่องกันเลย VVE ไม่ต้อง adopt 4-level mute เพราะ VVE ใช้ B-Roll ที่ generate มาจาก AI (ไม่มี original audio อยู่แล้ว) — แต่ถ้าอนาคต VVE ใช้ stock footage ที่มีเสียง เรื่องนี้จะ relevant

### ❓ 7-File JSON Sync — ไฟล์ที่เหลือเกี่ยวกับอะไร? จำเป็นไหม?

จาก source code ของ `video-autopilot-kit/draft_io.py` (M18 lesson) อธิบายว่า CapCut Desktop จัดเก็บ draft project เป็นหลายไฟล์:

| # | ไฟล์ | หน้าที่ | VVE sync ไหม? |
|---|------|--------|--------------|
| 1 | `draft_content.json` | **ไฟล์หลัก** — timeline, tracks, segments, materials ทั้งหมด | ✅ VVE เขียนไฟล์นี้ |
| 2 | `draft_content.json.bak` | Backup ของไฟล์หลัก — CapCut อ่านตัวนี้ถ้าตัวหลักพัง | ✅ VVE copy ทับ `.bak` |
| 3 | `draft_info.json` | Metadata ของ project (ชื่อ, thumbnail, created date) — macOS ใช้เป็นตัวหลักแทน `draft_content.json` ในบาง version | ❌ VVE ไม่ sync |
| 4 | `draft_content.json.tmp` | Temp file ที่ CapCut เขียนระหว่างบันทึก | ❌ VVE ไม่ sync |

| 7 | `.bak_vve` | VVE's own backup (ไม่ใช่ไฟล์ CapCut แต่เป็นที่เราสร้างเอง) | ✅ VVE สร้างเอง |

### ❓ Zod Validation — คืออะไร? ทำงานยังไง? จำเป็นไหม?

**Zod คืออะไร:** เป็น TypeScript library สำหรับ **validate input data ก่อนประมวลผล** — เหมือนยาม (guard) ที่ตรวจว่าข้อมูลที่ส่งเข้ามาถูกรูปแบบไหม ก่อนจะยอมให้ code ทำงาน

**ตัวอย่างจาก capcut-mcp-server:**
```typescript
// Zod schema — กำหนดว่า "add_text" ต้องรับค่าอะไรบ้าง
const AddTextSchema = z.object({
  text: z.string().min(1),                    // ต้องเป็น string ไม่ว่าง
  font: z.string().default("Montserrat"),      // font มี default
  fontSize: z.number().min(12).max(200),       // ขนาด 12-200 เท่านั้น
  color: z.string().regex(/^#[0-9A-Fa-f]{6}$/), // ต้องเป็น hex color
  positionY: z.number().min(-1).max(1),        // Y position -1 ถึง 1
  startTime: z.number().nonnegative(),         // ต้อง >= 0
});

// ถ้าส่ง { text: "", fontSize: 500 } → Zod จะ reject ทันที พร้อม error message ชัดเจน
```

**เทียบกับ VVE:**
```python
# VVE ตอนนี้ — ไม่มี validation
seg['target_timerange']['start'] = current_target_time  # ถ้า current_target_time เป็น negative?
seg['target_timerange']['duration'] = duration_us       # ถ้า duration_us เป็น 0?
# → CapCut จะเปิดได้แต่ timeline พัง — ไม่มีใครบอกว่าผิดตอนไหน
```

**ถ้า VVE จะทำ (ใช้ Pydantic แทน Zod เพราะเป็น Python):**
```python
from pydantic import BaseModel, Field

class TimeRange(BaseModel):
    start: int = Field(ge=0)           # ต้อง >= 0
    duration: int = Field(gt=0)        # ต้อง > 0

class SubtitleConfig(BaseModel):
    font_size: float = Field(ge=12, le=200)
    position_y: float = Field(ge=-1, le=1)
    color: str = Field(pattern=r'^#[0-9A-Fa-f]{6}$')

# ใช้:
config = SubtitleConfig(font_size=55, position_y=-0.364583, color="#FFFFFF")
# ถ้าใส่ผิด → Pydantic แจ้ง error ทันที ก่อนเขียน JSON
```

**VVE จำเป็นต้องมีไหม?**

| สถานการณ์ | จำเป็น? | เหตุผล |
|-----------|---------|--------|
| Pipeline ปกติ (input มาจาก script ก่อนหน้า) | **ไม่จำเป็นเร่งด่วน** | Input มาจาก VVE scripts เอง ไม่ใช่ user input — ถ้าผิดจะ catch ได้จาก QA step |
| ขยาย pipeline ให้รับ config จาก YAML | **ควรมี** ⚠️ | User พิมพ์ config เอง → ผิดง่าย → Pydantic ช่วยจับ error ก่อน inject |
| ทำหลาย channel (ไม่ใช่แค่ DoctorBank) | **ควรมี** ⚠️ | แต่ละ channel มี config ต่างกัน → validation ป้องกัน config ผิด format |

> **สรุป: ตอนนี้ยังไม่จำเป็น** — VVE pipeline เป็น closed system (script → script) ไม่มี external input ที่คาดเดาไม่ได้ แต่ถ้าอนาคตเปิดให้ config จาก YAML/user input → Pydantic validation จะมีค่ามาก

- **ถ้าจะทำหลาย channel → ควรทำ** — แยก typography config ออกมาเป็น YAML จะประหยัดเวลามาก

### ❓ CapCut เปลี่ยน JSON Schema — pyCapCut vs VVE ต่างกันอย่างไร?

**สถานการณ์:** CapCut อัพเดท version → เปลี่ยนโครงสร้าง `draft_content.json` (เพิ่ม field ใหม่ / เปลี่ยนชื่อ field / เปลี่ยน data type)

**VVE จัดการยังไง (ปัจจุบัน):**
```
CapCut อัพเดท → draft_content.json เปลี่ยน schema
    ↓
VVE capcut_editor.py เขียน JSON ตาม schema เก่า
    ↓
CapCut เปิด draft → อ่านไม่ออก / แสดงผลผิด / crash
    ↓
มึงต้อง debug เอง:
  1. เปิด CapCut ใหม่ ดู JSON structure ใหม่
  2. เทียบกับ code ว่าตรงไหนเปลี่ยน
  3. แก้ capcut_editor.py ให้ตรงกับ schema ใหม่
  4. test ว่า OK
    ↓
⏱️ ใช้เวลาอาจ 1-2 ชม. ถึง 1-2 วัน
```

**pyCapCut จัดการยังไง:**
```
CapCut อัพเดท → draft_content.json เปลี่ยน schema
    ↓
Community ของ pyCapCut (1.2k+ stars จาก pyJianYingDraft) สังเกตเห็น
    ↓
Maintainer แก้ library → push update ไป PyPI
    ↓
มึงแค่ `pip install --upgrade pycapcut`
    ↓
⏱️ ใช้เวลา 5 วินาที (แต่ต้องรอ maintainer fix ก่อน — อาจ 1-3 วัน)
```

**เปรียบเทียบ:**

| | VVE (DIY JSON) | pyCapCut (Library) |
|--|---|---|
| **ใครแก้?** | มึงแก้เอง | Community + maintainer แก้ให้ |
| **รู้เร็วแค่ไหน?** | รู้ตอน pipeline พัง | รู้จาก GitHub issues + changelog |
| **ควบคุมได้ไหม?** | **ควบคุมได้ 100%** 🏆 | ต้องรอ maintainer (อาจ 1-3 วัน) |
| **Risk ถ้า library ถูก abandon?** | ไม่มี risk | **เป็น risk จริง** ⚠️ — ถ้า maintainer หยุดดูแล ก็ต้องกลับมา DIY |
| **CapCut version ที่ support?** | Support ทุก version (เพราะเขียนเอง) | Support เฉพาะที่ maintainer test |
| **ตัวอย่างที่เคยเกิด** | VVE `capcut_reader.py` เพิ่ม `template-2.tmp` เมื่อ CapCut 8.8.0+ เปลี่ยน | pyJianYingDraft เคยมี issue เมื่อ Jianying 6.0+ encrypt draft |

> **สรุป:** VVE approach (DIY JSON) **ยืดหยุ่นกว่า** — ไม่ต้องพึ่งคนอื่น ควบคุมได้ 100% แต่ต้อง debug เอง pyCapCut **สะดวกกว่า** — แต่ถ้า library ไม่ update ตามทัน ก็ติดอยู่ดี

> สำหรับ VVE ที่ทำแค่ **1 channel (DoctorBank)** + **1 เครื่อง** + **CapCut version ค่อนข้าง stable** → DIY JSON ที่ทำอยู่ตอนนี้ **เพียงพอ** ไม่จำเป็นต้องพึ่ง library ภายนอก
