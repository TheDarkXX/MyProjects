- **สาเหตุ:** การดึงหน้า FB Reel ผ่าน server-side ไม่มี `Sec-Fetch-Mode: navigate` / `Sec-Fetch-Dest: document` ทำให้ Facebook ตอบกลับ `HTTP 400`, กรอบสแกน `"title"` แคบเกินไป, และ Extension ยังไม่มี Fallback ดึง HTML หน้า FB Reel ด้วย Cookie ของเบราว์เซอร์โดยตรง
- **การแก้ไขฝั่ง Extension (`manifest.json`, `background.js`, `sidepanel.js`):**
  - เพิ่ม `"https://*.shopee.co.th/*"` ใน `host_permissions` ของ `manifest.json`
  - เพิ่ม `scrapeFbReelHtmlAuthenticated()`, `resolveShopeeShortUrlInExt()`, `extractShopeeTagFromHtml()`, `normalizeShopeeShortUrl()`, และ `extractShopeeShopItemFromUrl()` ใน `background.js` เพื่อแกะ `link_uri` / `external_url` (รวมถึง `l.facebook.com/l.php` / `flx/warn`) และคลาย Redirect หลายชั้นหา `shop_id` / `item_id`
  - อัปเกรด `scrapeActiveFacebookReelTabImpl` และ `SPY_COLLECT_REELS` ให้เสริมข้อมูล FB Reel ด้วย Session ของเบราว์เซอร์ก่อนส่งเข้าเซิร์ฟเวอร์

### 2. แก้บั๊กดึงค่าคอมผิดเป็น `EXTRACOMM 0% / Base 0.6%` ทั้งที่หน้า AFF มีเรทจริง (`5% + 2%`)

  2. ใน `/api/v3/offer/product/list` มีคีย์ `commission_rate_detail: {}` ว่างๆ หลอก `extractListCommissionFallback()` ใน `src/common/utils.js` ให้มองข้าม `seller_commission_rate` / `max_commission_rate` / `default_commission_rate`

  4. `drbRealOfferCacheV1` ใน `background.js` เก็บรายการ `0.6%` เก่าไว้และ `sidepanel.js` ไม่ได้ `forceRefresh` เมื่อ `extraRate <= 0`
- **การแก้ไข:**
