# Indicator Config ColorPicker & Subsystem toUpperCase Hardening

## 📌 Context & Implementation (Compiled Truth)
- **Root Cause 1 (`ColorPickerDropdown`)**: Clicking the gear icon `⚙️ Configure EMA Ribbon` in `MainPaneIndicatorLegend` opened `IndicatorManagerPopover` in `'ema'` view. The `ColorPickerDropdown` executed `setHexInput(color.toUpperCase())` on mount. When user config from `localStorage` had undefined/null `color` for `ema4`/`ema5`, this immediately threw `Cannot read properties of undefined (reading 'toUpperCase')`, crashing the application into the global Error Boundary.
- **Root Cause 2 (`useHoldings`)**: Cash transactions without symbols polluted `holds` with `"undefined"`, propagating ghost holdings downstream.
- **Defensive Hardening Implemented**:
  1. `IndicatorManagerPopover.tsx`: Fully resilient `ColorPickerDropdown` with default `#FFFFFF`, safe uppercase conversion, safe hex styling, and robust `emaLines` mapping with default fallbacks.
  2. `useIndicatorStore.ts`: `loadSavedConfig()` guarantees fallback `color` and `name` properties for `ema1`-`ema5`. `addCustomColor` enforces string type checks and safe trimming.
  3. Safe guards across `StockLogo.tsx`, `CompareConfigModal.tsx`, `CompareLWChart.tsx`, and `TransactionFormModal.tsx`.
- **Build & Deploy**: `npm run build` cleanly passed, cache bumped to `v=20261006_001459`, committed to Git, and synced to VPS `185.250.38.247` with PM2 reload.
