# V2.7.0: Actionable Trade Execution Engine with Technical Intelligence & Consensus History

## 📌 Context & Implementation (Compiled Truth)

### Why this was built
ก่อนหน้านี้คำแนะนำของ AI Advisor สั่งเพียงแค่ "REDUCE 7.5%" หรือ "ADD 5%" แบบลอยๆ ไม่มีกลยุทธ์การเทรดที่ชัดเจน ผู้ใช้ไม่รู้ว่าควรแบ่งไม้ขายอย่างไร ตั้งจุดตัดขาดทุนตรงไหน หรือทำอย่างไรไม่ให้ขายหมู (House Money vs Cut Loss).
V2.7.0 พัฒนา **Actionable Trade Execution Engine** พร้อม **Technical Intelligence** ยกระดับคำแนะนำสู่ระดับ Quant & Institutional Trading Desk:
1. **Quant Engine ในเครื่อง**: คำนวณ Wilder's Smoothing RSI(14), ATR(14), SMA(20), 20-Day Support/Resistance Pivots, และ 2×ATR Trailing Stop จากแท่งเทียน OHLC สด 45 วันทำการ โดยแยก In-Memory Cache 4 ชม. ไม่ให้อิงกับแคชพื้นฐาน 24 ชม.
2. **Consensus Tracking Ledger**: สร้างตาราง SQLite `consensus_history` บันทึกค่าเฉลี่ยเป้าหมายราคาของ Wall Street รายวัน พร้อมกลไก Daily Deduplication (UPSERT) เพื่อเป็น Moat ในการวัด Accuracy ย้อนหลัง
3. **Pre-computed Tranches & Action Needed**: ฝั่ง Backend คำนวณมูลค่าเงินและจำนวนหุ้นที่ต้องปรับล่วงหน้า (`action_needed`) ส่งเข้า AI เพื่อลดภาระการคำนวณ ป้องกัน Hallucination และประหยัด Token ได้กว่า 40%
4. **3 Execution Archetypes (โหมด Strategist)**:
   - `CONSERVATIVE`: ทยอยแบ่งไม้ (50/50) ตามแนวรับ/แนวต้าน 20 วัน
   - `TREND_FOLLOWING`: ขายทำกำไรบางส่วน (30%) และตั้ง Trailing Stop (70%) ห่าง 2×ATR ป้องกันขายหมู
   - `AGGRESSIVE`: เคาะราคาตลาด 100% ไม้เดียวจบสำหรับกรณีคัทลอสหรือตัดเนื้อร้ายนอกพิมพ์เขียว
5. **Interactive UI & Copy Trade Slip**: แสดงผลด้วย `ExecutionStrategyCard` มี Tranche Bar Visualizer และปุ่มคลิกเดียว 📋 คัดลอกคำสั่งสำหรับส่งเข้าแอปเทรดหุ้นทันที

## 🔴 จุดวิกฤตที่ต้องอุดก่อนลงโค้ด (Critical Blind Spots)

### 1. Token Budget Bomb 💣 — Schema ใหญ่เกิน `max_tokens: 8000`
- เพิ่ม `max_tokens` เป็น `12000` สำหรับ strategist mode
- Pre-compute ตัวเลข Tranche ฝั่ง Backend ก่อนส่งเข้า AI
- จำกัด executionStrategies เฉพาะ Top-3 suggestions ที่มีน้ำหนักมากสุด

### 2. OHLC Data Freshness vs Fundamentals TTL 🕐
- แยก OHLC Historical เป็นฟังก์ชันอิสระ `fetchOHLC(symbol)` ใน `technicalAnalysis.js` ที่มี TTL สั้นกว่า (4-6 ชั่วโมง)
- อย่ายัดเข้า `yahooFundamentals.js`

### 3. SMA50/SMA200 มีอยู่แล้ว — อย่าคำนวณซ้ำ ♻️
- `priceVsSma50` และ `priceVsSma200` ให้คำนวณจาก `fundamentals.sma50` / `fundamentals.sma200` ที่มีอยู่
- Quant Engine คำนวณเฉพาะสิ่งที่ Yahoo ไม่ให้: RSI(14), ATR(14), SMA(20), 20-Day S/R Pivots
- ดึง 45 วันทำการปลอดภัยครบทุกตัวชี้วัด

### 4. Consensus Snapshot — ต้องมี Date-Level Deduplication 📅
- ตาราง `consensus_history` PRIMARY KEY `(symbol, snapshot_date)`
- บันทึก `current_price` ณ วันนั้นด้วย

### 5. Schema Backward Compatibility — Old Cache จะพัง Frontend 🧨
- Frontend Guard clause: `if (!suggestion.executionStrategies?.options?.length) return <SimpleSuggestionCard />`
- Cache Invalidation ใน backend

### 6. Execution Strategies ควร Gate เฉพาะ Strategist Mode 🚪
- Gate ไว้ใน `isStrategist` block เดียวกัน

### 7. Missing: Risk/Reward Ratio (R:R) ต่อ Tranche ⚖️
- แนบแนวรับแนวต้านและ Trailing Stop
