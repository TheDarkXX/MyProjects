# Reality-First AI Portfolio Advisor: Dual-Layer Actual Holdings Engine & Intelligent Drift Notes (V2.6.0)

## 💡 Context & Implementation (Compiled Truth)

### 1. Root Cause & Critical Flaw Addressed:
In V2.5.0 and earlier, the AI Portfolio Advisor (โหมด Strategist จอมมารแห่ง Wall Street) suffered from a fundamental architectural flaw:
1. **Blind to Reality (มองไม่เห็นพอร์ตจริง):** The frontend only transmitted the template blueprint targets (`blueprints.target_percent`) to the backend AI engine. It completely omitted real user holdings (`holdings`), actual invested costs (`avgCost`), accrued P&L (`totalReturnPercent`), actual cash balances, and holding weights.
2. **AI Misconception of Portfolio Structure:** Because the AI only received ideal blueprint targets, it assumed the user already held that portfolio composition. Metrics like weighted Beta, average P/E, sector distribution, and Risk Score reflected a "dream blueprint" rather than the real-world risk exposure.
3. **Misleading "Before vs After" Donut:** The Before/After chart in the "แผนปรับพอร์ต" tab compared *Previous Blueprint Target* vs *AI Recommended Ideal Blueprint*, rather than *What the user actually owns today* vs *AI Target*.
4. **Toothless Action Roadmap & Ignored Orphan Stocks:** If a user owned stocks outside of their blueprint (e.g. holding depreciating speculative stocks like INTC or BABA not in their blueprint list), the AI was completely blind to them. It could not order ruthless divestments (`CUT 100%`) or tell the user which assets to liquidate to fund new target allocations.
5. **Duplicate Action Buttons & Missing Status Notes:** When cached results were loaded, the card header rendered a prominent gradient `[ 🔄 วิเคราะห์ใหม่ ]` button while the status banner directly beneath rendered another identical `[ 🔄 วิเคราะห์ใหม่ ]` button in the exact same column, creating visual clutter and confusing users without explaining whether portfolio proportions or stocks had actually changed.

---

### 2. Dual-Layer "Reality-First" Engine Architecture:
We overhauled the end-to-end data pipeline between client and server into a dual-layer evaluation model:

```
[User Portfolio Store]
   ├── Actual Holdings (holdings, cashBalance, cashWeight, P&L, avgCost, currentPrice)
   └── Target Blueprint (blueprints with target_percent & categories)
             │
             ▼
[AIBlueprintAdvisor.tsx]
   ├── Gathers Full Universe of Symbols (Holdings ∪ Blueprints)
   ├── Fetches Yahoo Fundamentals Batch for All Real & Planned Stocks
   ├── Computes Cockpit Metrics (Beta, P/E, Cash %, Sectors) based on ACTUAL holdings
   └── Packages `actualHoldingsPayload` into `api.ai.advisor()`
             │
             ▼
[POST /api/ai/advisor] -> compressPromptData()
   ├── Evaluates Mode: REALITY_FIRST (if actual holdings exist) vs BLUEPRINT_SANDBOX (fallback)
   ├── Classifies Assets: Identifies Orphan Assets (is_orphan = true) held in reality but missing in blueprint
   ├── Feeds Dual-Layer Data to System Prompt:
   │     - ACTUAL_PORTFOLIO (Real positions, weights, market value, P&L %, orphan flags)
   │     - TARGET_BLUEPRINT (User's planned targets)
   └── Directs Hermes GPT-5.6 Terra (Ruthless Wall Street Strategist):
         - "เปรียบเทียบจุดที่ยืนอยู่จริงกับเป้าหมาย"
         - "สั่งตัดเนื้อร้าย (Orphan assets) ทิ้ง 100% เพื่อดึงกระสุนเงินสด"
         - "ออกคำสั่ง Action Roadmap ระบุชื่อหุ้นที่ต้องขายจริงและนำเงินไปซื้อตัวไหน"
```

---

### 3. Intelligent Drift Detection & Note Badging System:
To eliminate duplicate button clutter and provide explicit explanations of portfolio changes, we built client-side drift analytics (`driftDetails`):

1. **Comparison Matrix:**
   - Compares current `blueprints` against `aiResult.idealBlueprint` and `aiResult.stockVerdicts`.
   - Compares actual `holdings` against analyzed holdings to detect newly purchased assets.
   - Detects added symbols (`addedBpSymbols`), removed symbols (`removedBpSymbols`), target percentage drifts (`percentChanges` where $|\Delta| \ge 0.5\%$), and newly detected real-world holdings (`newHoldingsSymbols`).
2. **Single Primary Action Button:**
   - Eliminated the secondary button inside the sub-bar.
   - Enhanced the header button with dynamic state:
     - **Unchanged:** Gradient purple-indigo-amber `[ 🔄 วิเคราะห์ใหม่ ]`
     - **Drift Detected:** Vibrant amber-orange-rose pulse `[ 🔄 วิเคราะห์ใหม่ (ข้อมูลเปลี่ยน) ]`
3. **Informative Change Remark Banner (หมายเหตุการเปลี่ยนแปลง):**
   - **When Synchronized (`!hasDrift`):** Shows green pulsing indicator and explicit confirmation:
     `✓ หมายเหตุ: สัดส่วนและรายชื่อหุ้นตรงกับผลวิเคราะห์ (ไม่มีข้อมูลเปลี่ยนแปลง)`
   - **When Drift Detected (`hasDrift`):** Renders amber notice banner detailing exact changes:
     - `+ เพิ่มหุ้นใหม่ในพิมพ์เขียว: [SYM]`
     - `- ตัดหุ้นเดิมออกจากพิมพ์เขียว: [SYM]`
     - `⚖️ ปรับสัดส่วนเป้าหมาย: SYM (เดิม% ➔ ใหม่%)`
     - `💼 พบหุ้นใหม่ในพอร์ตจริง: [SYM]`
     - Subtext: `👉 แนะนำให้กดปุ่ม "วิเคราะห์ใหม่ (ข้อมูลเปลี่ยน)" ที่มุมบนขวา เพื่อให้ระบบประเมินและจัดพอร์ตตามโครงสร้างล่าสุด`

## ที่มาและปัญหาเชิงโครงสร้าง (Critical Flaw & Context)

ปัจจุบันระบบ **AI Portfolio Advisor (โหมด Strategist จอมมารแห่ง Wall Street)** มีจุดบอดร้ายแรงในระดับรากฐาน (Architectural Blind Spot):
1. **AI มองไม่เห็นความเป็นจริง (Blind to Actual Reality):** ระบบส่งเฉพาะสัดส่วนในเทมเพลต (`blueprints.target_percent`) ไปให้ AI ประเมิน โดยไม่ได้ส่งข้อมูลหุ้นที่ถือจริง (`holdings`), ต้นทุนจริง (`avgCost`), กำไร/ขาดทุนสะสม (`totalReturnPercent`) หรือสัดส่วนจริง (`actualPercent / weightPercent`)
2. **LLM เข้าใจผิดว่าผู้ใช้ถือหุ้นตามเทมเพลตอยู่แล้ว:** เมื่อ AI ได้รับเฉพาะตัวเลข Blueprint มันจึงสมมุติว่าพอร์ตปัจจุบันของผู้ใช้คือ Blueprint นั้น ทำให้ตัวเลข Beta รวม, P/E ถ่วงน้ำหนัก, และคะแนนความเสี่ยง (Risk Score) สะท้อนแค่ "พอร์ตในฝัน" ไม่ใช่ "พอร์ตที่มีอยู่จริง"
3. **Before vs After หลอกตา:** ใน Tab "แผนปรับพอร์ต" การเปรียบเทียบ Before vs After กลายเป็นการเทียบระหว่าง *Blueprint เดิม* กับ *Ideal Blueprint ของ AI* ไม่ได้เทียบจาก *สิ่งที่ถือจริงในมือ*
4. **Action Roadmap และคำสั่งฟันธงไร้ประโยชน์จริง:** AI ไม่สามารถสั่ง "เชือดหุ้นเน่า" ที่ผู้ใช้ติดดอยอยู่จริงได้ ถ้าหุ้นตัวนั้นไม่ได้ถูกใส่ไว้ในเทมเพลต Blueprint และไม่รู้ว่าต้องขายตัวไหนจริงเพื่อดึงเงินสดออกมาเติมหุ้นตัวใหม่

## 1. ปัญหาเดิม & จุดที่ได้รับการแก้ไข (Root Cause & Solution)

| ส่วนประกอบ | ก่อนแก้ไข (V2.5.0) | หลังแก้ไข (V2.6.0 Reality-First) |
|---|---|---|
| **Data Scope ที่ส่งให้ AI** | ส่งเฉพาะ `blueprints.target_percent` (สัดส่วนในฝัน) | ส่งทั้ง **`actualPortfolio`** (สัดส่วนจริง, ต้นทุน, P&L, เงินสดจริง) และ **`targetBlueprint`** |
| **ความเข้าใจของ AI ต่อพอร์ต** | AI คิดไปเองว่าผู้ใช้ถือหุ้นตาม Blueprint อยู่แล้ว | AI ตรวจสอบพอร์ตจริงก่อนเสมอ ชี้หน้าหุ้นเน่า ติดดอย หรือหุ้นนอกแผน |
| **การจัดการหุ้นนอกแผน (Orphan Assets)** | หุ้นที่ถือจริงแต่อยู่นอก Blueprint ถูก AI มองข้าม 100% | ตรวจพบเป็น `is_orphan = true` และออก Verdict สั่ง `CUT 100%` ทันที |
| **Before vs After Donut** | เปรียบเทียบระหว่าง *Blueprint เดิม* vs *Ideal Blueprint* | ฝั่งซ้ายแสดง **"พอร์ตจริงปัจจุบัน (Actual Holdings %)"** vs ฝั่งขวา **"พิมพ์เขียวแนะนำใหม่ (Ideal Blueprint %)"** |
| **ตารางพิมพ์เขียวเป้าหมาย** | มีแค่คอลัมน์ ปัจจุบัน vs แนะนำ | เพิ่มคอลัมน์ชัดเจน: **สัญลักษณ์** \| **พอร์ตจริง** \| **แผนคุณ** \| **AI แนะนำ** \| **การปรับทัพ** \| **ส่วนต่าง** |
| **การ์ดหุ้นรายตัว (StockVerdictCard)** | แสดงเฉพาะข้อมูล Wall Street | แสดงป้ายกำกับสถานะการถือครองจริง: `💼 ถืออยู่จริง 15.4% (+25.3%)` หรือ `⚠️ นอกแผน` หรือ `🎯 ยังไม่มีของ` |
| **Action Roadmap** | สั่งการลอยๆ จากตัวเลข Blueprint | สั่งการจากของจริง: ระบุชื่อหุ้นในพอร์ตที่ต้องตัดขายเพื่อดึงเงินสดไปเติมพิมพ์เขียว |

## 4. จัดการปุ่มซ้ำซ้อน & เพิ่มหมายเหตุสัดส่วน/หุ้นเปลี่ยน (V2.6.1 UI Refinement)

### สาเหตุที่ปุ่มซ้ำซ้อน (Root Cause)
- ในหัวการ์ด (Header Bar) มีปุ่ม Primary Action `[ 🔄 วิเคราะห์ใหม่ ]` อยู่แล้ว
- ในแถบสถานะแคช (Status Strip) ด้านล่างกลับมีปุ่ม `[ 🔄 วิเคราะห์ใหม่ ]` อีกปุ่มหนึ่งซ้อนอยู่ตรงคอลัมน์เดียวกัน ทำให้เกิดปุ่มซ้อนกัน 2 ชั้น

### แนวทางแก้ไข
1. **ตัดปุ่มซ้ำซ้อนออก 100%:**
   - รวม Action ไว้ที่ปุ่มหลักมุมขวาบนของ Header Bar เพียงจุดเดียว
   - หากข้อมูลพอร์ตหรือพิมพ์เขียวมีการเปลี่ยนแปลง ปุ่มหลักจะเปลี่ยนเป็นสถานะเตือนสีส้มทอง `[ 🔄 วิเคราะห์ใหม่ (ข้อมูลเปลี่ยน) ]` พร้อมเอฟเฟกต์ pulse ทันที
2. **เพิ่มแถบหมายเหตุการเปลี่ยนแปลงแบบเจาะจง (Intelligent Drift Notes):**
   - **กรณีข้อมูลตรงกัน:** แถบสถานะสีเขียวระบุชัดเจน `✓ หมายเหตุ: สัดส่วนและรายชื่อหุ้นตรงกับผลวิเคราะห์ (ไม่มีข้อมูลเปลี่ยนแปลง)`
   - **กรณีมีการปรับเปลี่ยน:** แสดงการ์ดเตือนสีอำพันพร้อม Badge ชี้เป้าว่ามีอะไรเปลี่ยนบ้าง:
     - `+ เพิ่มหุ้นใหม่ในพิมพ์เขียว: [SYM]`
     - `- ตัดหุ้นเดิมออกจากพิมพ์เขียว: [SYM]`
     - `⚖️ ปรับสัดส่วนเป้าหมาย: SYM (เดิม% ➔ ใหม่%)`
     - `💼 พบหุ้นใหม่ในพอร์ตจริง: [SYM]`
     - คำแนะนำ: ให้กดปุ่ม "วิเคราะห์ใหม่ (ข้อมูลเปลี่ยน)" ที่มุมขวาบนเพื่ออัปเดตผลประเมินล่าสุด
