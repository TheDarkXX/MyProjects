### 1. วัตถุประสงค์และการปรับปรุงเชิงยุทธศาสตร์ (Strategic Purpose)
- **โจทย์ที่ 1 (Watchlist Sorting บน MyPort Watchlist):**
  - ในหน้าต่าง Watchlist ฝั่งขวาของ X-Chart (เมื่อเลือกแท็บ `My Port` ตามภาพตัวอย่าง) เดิม Header คอลัมน์ `Symbol`, `Last`, `Chg`, `Chg%` เป็นเพียง `<div>` แสดงข้อความธรรมดา ไม่สามารถคลิกจัดเรียงได้ และรายการหุ้นถูกแสดงตามลำดับที่ได้จาก API/ฐานข้อมูล
  - **ความต้องการผู้ใช้:** เพิ่มระบบ Sorting ให้สามารถกดเรียงข้อมูลที่คอลัมน์ `Symbol`, `Last`, `Chg`, และ `Chg%` ได้ทั้งแบบ `desc` / `asc` โดยกำหนดให้ **`Chg% desc (ติดลบเยอะสุดอยู่บนสุด)`** เป็นค่า Default
  - **เหตุผลทางธุรกิจ/การเทรด:** ในการสแกนพอร์ตและติดตามตลาด นักลงทุนต้องการเห็นหุ้นตัวที่โดนทุบหนักที่สุดหรือย่อตัวลึกที่สุดอยู่แถวบนสุดทันที เพื่อประเมินความเสี่ยงและหาจังหวะช้อนซื้อ (Buy on Dip)

- **โจทย์ที่ 2 (การแยกบันทึกการตั้งค่ากราฟรายแท็บ & Cloud Sync):**
  - ในแถบ Tab Bar ด้านบนของ X-Chart ผู้ใช้เปิดหลายแท็บคู่ขนานกัน เช่น แท็บหุ้น (`META`), แท็บค่าเงิน (`USD/THB`), แท็บภาพรวม (`Market Heatmap`), และแท็บพอร์ต (`My Port`)
  - **ปัญหาเดิม (Global State Leak):** การตั้งค่ากราฟ (Timeframe, Chart Style, Resolution) และ Indicator ทั้งหมด (EMA, Envelope, SuperMoneySignal, MCDX, RSI, TrendSpeed, ความสูง Sub-panes) ถูกผูกติดกับ Global Store ก้อนเดียว ทำให้เวลาปรับค่าที่แท็บหนึ่ง (เช่น เปิด MCDX บน META) มันลามไปกระทบแท็บค่าเงิน USD/THB หรือแท็บอื่นๆ ทั้งหมด
  - **ความต้องการผู้ใช้:** แต่ละแท็บต้องมีการบันทึกการตั้งค่ากราฟต่างๆ แยกกันต่างหากโดยอิสระ ไม่ลิ้งกัน และมีระบบ Auto Sync ขึ้น Cloud VPS ตามแต่ละแท็บ
  - **ข้อเสนอ Full Cloud Sync 100% (ผู้ใช้อนุมัติ):** ทุกส่วนที่เคยบันทึกเฉพาะใน `localStorage` ของเครื่อง (เช่น Sorting Preference, สถานะการพับกางหมวดหมู่, และการตั้งค่ากราฟแต่ละแท็บ) ต้องถูกยกระดับขึ้น Cloud VPS ทั้งหมด เพื่อให้การใช้งานข้ามอุปกรณ์ (Desktop, iPad, มือถือ, โน้ตบุ๊ก) มีความสอดคล้องกันแบบ Zero Device Discrepancy

#### 2.2 ตรรกะการประสานงานระหว่าง `useIndicatorStore` และ `xchartStore` (Decoupled Sync Pattern)
เพื่อหลีกเลี่ยง Circular Dependency ระหว่าง Zustand Stores:
1. ใน `useIndicatorStore.ts` สร้าง Event Listener:
   ```typescript
   let tabSyncListener: ((tabId: string, config: IndicatorSettings) => void) | null = null;
   export function registerTabIndicatorSync(fn: (tabId: string, config: IndicatorSettings) => void) {
     tabSyncListener = fn;
   }
   ```
2. เมื่อมีการเปลี่ยนแปลง Indicator ใดๆ ฟังก์ชัน `saveConfig` จะเรียก `tabSyncListener(activeTabId, config)`
3. ใน `xchartStore.ts` ลงทะเบียน:
   ```typescript
   registerTabIndicatorSync((tabId, config) => {
     useXChartStore.getState().updateTabChartSettings(tabId, { indicatorSettings: config });
   });
   ```
4. เมื่อสลับแท็บ (`setActiveTabId` ใน `xchartStore` หรือ `useEffect` ใน `XChartPanel`):
   ```typescript
   if (activeTab.settings?.indicatorSettings) {
     useIndicatorStore.getState().loadTabConfig(id, activeTab.settings.indicatorSettings);
   }
   ```
5. เมื่อโหลดหรือซิงก์จาก Cloud VPS:
   ```typescript
   applyCloudTabs: (data) => {
     const mappedTabs = data.tabs.map(ensureTabSettings);
     // ...
     const activeTab = mappedTabs.find((t) => t.id === activeTabId);
     if (activeTab?.settings?.indicatorSettings) {
       useIndicatorStore.getState().loadTabConfig(activeTabId, activeTab.settings.indicatorSettings);
     }
   }
   ```

#### 2.3 ตรรกะการจัดเรียงใน MyPort Watchlist (`MyPortWatchlist.tsx`)
```typescript
export type MyPortSortColumn = 'symbol' | 'price' | 'change' | 'percentChange';
export type MyPortSortDir = 'asc' | 'desc';

export interface MyPortWatchlistPreferences {
  sortColumn: MyPortSortColumn;
  sortDir: MyPortSortDir;
  holdingsCollapsed: boolean;
  targetCollapsed: boolean;
}

export const DEFAULT_MYPORT_PREFERENCES: MyPortWatchlistPreferences = {
  sortColumn: 'percentChange',
  sortDir: 'desc', // 'desc' = ติดลบเยอะสุดอยู่บนสุด as default
  holdingsCollapsed: false,
  targetCollapsed: false,
};
```
- **ตรรกะการเปรียบเทียบ (Comparator Logic):**
  - **`Chg% desc (Default)`**: ติดลบมากสุดขึ้นก่อน `pctA - pctB` เช่น `-47.87%` -> `-2.52%` -> `-1.46%` -> `-0.16%` -> `+0.53%` -> `+2.44%`
  - **`Chg% asc`**: บวกมากสุดขึ้นก่อน `pctB - pctA`
  - **`Chg desc`**: เงินสดที่ลดลงมากสุดขึ้นก่อน `changeA - changeB`
  - **`Chg asc`**: เงินสดที่เพิ่มมากสุดขึ้นก่อน `changeB - changeA`
  - **`Price desc`**: ราคาสูงสุดขึ้นก่อน `priceB - priceA`
  - **`Price asc`**: ราคาต่ำสุดขึ้นก่อน `priceA - priceB`
  - **`Symbol asc`**: A -> Z `a.symbol.localeCompare(b.symbol)`
  - **`Symbol desc`**: Z -> A `b.symbol.localeCompare(a.symbol)`
- ประยุกต์ใช้ทั้งในอาร์เรย์ `sortedHoldings` (ส่วน Holdings) และ `sortedTargetStocks` (ส่วน Target · Project 2X)

## ตอบคำถาม: "ที่เอาลง localStorage เอา ขึ้น cloud ด้วยสิทุกส่วนเลย ดีไหม?"

> [!IMPORTANT]
> **คำตอบ: ดีมากและเป็นแนวทางที่ถูกต้องที่สุดในเชิง Macro Architecture!**
> 1. **Zero Device Discrepancy (ประสบการณ์ไร้รอยต่อข้ามอุปกรณ์):** เมื่อมึงตั้งค่าให้ `Chg% desc` ในคอม หรือจัดกราฟแท็บ `META` ให้มี MCDX ส่วนแท็บ `USD/THB` เป็นกราฟเปล่า พอหยิบมือถือ แท็บเล็ต หรือโน้ตบุ๊กมาเปิด ทุกอย่างจะตรงกัน 100% ทันที ไม่ต้องมานั่งคลิกจัดเรียงหรือเปิด-ปิด Indicator ซ้ำซาก
> 2. **กำจัด Orphan LocalStorage (ลดหนี้ทางเทคนิค):** การปล่อยให้แต่ละ Component แอบเขียน `localStorage.setItem('p2x_lw_timeframe')` หรือ `localStorage.setItem('myport_holdings_collapsed')` เป็น anti-pattern ที่ทำให้ state กระจัดกระจายและไม่สามารถ backup/restore ได้ การรวมศูนย์เข้า Cloud VPS ทำให้ระบบมี Single Source of Truth ชัดเจน
> 3. **Offline Resilience (ยังทำงานได้แม้ออฟไลน์):** สถาปัตยกรรมนี้ยังคงเขียนลง `localStorage` เป็น Cache สำรองในเครื่องคู่ขนานไปด้วยเสมอ ทำให้ตอนเปิดหน้าเว็บมาจะ Snappy ทันทีแบบ 0ms แล้วค่อยดึง/ดันการเปลี่ยนแปลงขึ้น Cloud VPS เบื้องหลัง
