# V2.28.1 [impl] UI: X-Chart 6s Hyper Pulse Engine, Real-Time Watchlist Dock Synchronization & Finnhub vs Yahoo Architecture Analysis

## 📌 Context & Implementation (Compiled Truth)

### 1. บริบทและวัตถุประสงค์ (Strategic Purpose)
หลังจากการส่งมอบระบบ **V2.28.0 (Real-Time Live Candlestick Engine & Watchlist Sorting)** ในช่วงดึก (01:18 - 01:47 น.) ผู้ใช้ได้เข้ามาตรวจสอบความพร้อมของระบบเมื่อเปิดตลาดจริง พร้อมตั้งคำถามเชิงสถาปัตยกรรมและสมรรถนะ:
1. **การตรวจสอบสถานะงานช่วงตี 1 - ตี 3:** ยืนยันความสมบูรณ์ของโจทย์ที่ 3 (Real-Time Live Candlestick & Pulse Engine) ว่าแท่งเทียนวันนี้พร้อมทำงานตอนตลาดเปิดหรือไม่
2. **ประเมินความเร็วและความเนียนเทียบกับ TradingView:** วิเคราะห์เปรียบเทียบระบบ Pulse Engine (12 วินาที) กับ TradingView จริง (WebSocket Streaming ระดับเสี้ยววินาที)
3. **การประเมินความเสี่ยงด้าน API Rate Limit:** วิเคราะห์เกราะป้องกัน 4 ชั้น (VPS Proxy, Backend In-Memory Cache, Batching, Smart Tab Visibility) ซึ่งยืนยันว่าการยิงเพียง 2-5 requests/นาที มีความปลอดภัยห่างไกลจากเพดาน 2,000 req/hr ของ Yahoo Finance
4. **ข้อเสนอใช้ Finnhub WebSocket สำหรับชาร์ตหลัก:** ผู้ใช้เสนอให้ใช้ Finnhub API Key ดึงราคา Real-time ระดับ Tick-by-Tick เฉพาะหุ้นที่เปิดดูบน X-Chart ในช่วงตลาดเปิด และให้ส่วนอื่นใช้ Yahoo เหมือนเดิม
5. **การวิเคราะห์กับดักทางสถาปัตยกรรม (The 3 Architectural Traps):**
   - **กับดักที่ 1 (Price Divergence):** ราคา Finnhub มาจากกระดาน Cboe/BATS ในขณะที่ Watchlist ของ Yahoo มาจาก Consolidated Tape (รวมทุกตลาด NYSE/NASDAQ) จะทำให้ตัวเลขบนจอเดียวกันเหลื่อมกัน 0.10 - 0.50 ดอลลาร์ตลอดเวลา
   - **กับดักที่ 2 (Illiquid Ghost Town):** หุ้นนอกกระแส/หุ้นปันผลไม่มีการซื้อขายบน Cboe เป็นเวลานาน ทำให้กราฟบนชาร์ตนิ่งสนิทเหมือนค้าง ทั้งที่ในตลาดจริงมีวอลุ่ม
   - **กับดักที่ 3 (High/Low Incompleteness):** ข้อมูล Trade บน WebSocket ไม่ส่งค่า High/Low รวมของทั้งตลาด ทำให้ไส้เทียนของวันนั้นอาจจะสั้นกว่าราคาจริง
6. **การตัดสินใจเลือกทางออก (Option A: 6s Hyper Pulse):**
   - ผู้ใช้เลือก **"ทางเลือก A (ปรับ 5-6 วิ เนียน ตรงเป๊ะทั้งจอ)"**
   - เร่ง Heartbeat ของชาร์ตจาก 12 วินาทีเป็น **6 วินาที**
   - ปรับแคชหลังบ้านจาก 30 วินาทีเป็น **5 วินาที**
   - ซิงก์ราคาเข้า `useXChartStore.watchlistPrices` เพื่อให้หน้าต่าง Watchlist Dock ด้านขวาและ MyPort Watchlist ได้รับราคาชุดเดียวกันเป๊ะกับแท่งเทียนของชาร์ตแบบ Zero Discrepancy

## 📦 RAW ARTIFACT BACKUP (Iron Rule)

### Architecture Decision Record: Finnhub WebSocket vs Yahoo Polling
```markdown
# ADR: Real-time Price Streaming Architecture Analysis

## Context
ผู้ใช้สอบถามความเป็นไปได้ในการนำ Finnhub API Key (ตัวฟรี) มาต่อ WebSocket (`wss://ws.finnhub.io`)
เพื่อสตรีมราคาหุ้น Tick-by-Tick เฉพาะหุ้นตัวที่กำลังเปิดดูกราฟใน X-Chart
และคงส่วน Watchlist / พอร์ตโฟลิโอ ไว้ที่ Yahoo Finance ทุก 12 วินาที

## Analysis & Traps
1. REST API Rate Limit: Finnhub Free จำกัดที่ 60 requests/minute และไม่มี Batch Quote สำหรับ Free Tier ทำให้ใช้เฝ้า Watchlist ทั้งหมดไม่ได้
2. WebSocket Data Source: สัญญาณ Free WebSocket ของ Finnhub ไม่ใช่ Consolidated Tape ของตลาดสหรัฐฯ แต่ดึงมาจากกระดาน Cboe (BATS/IEX) เท่านั้น
3. Price Divergence Risk: หากชาร์ตแสดงราคา Cboe ($582.10) แต่ Watchlist ขวามือแสดงราคา Consolidated ของ Yahoo ($582.45) ผู้ใช้จะเห็นราคาไม่ตรงกันบนหน้าจอเดียวกัน
4. Illiquid Stock Freezing: หุ้นปันผล หุ้นขนาดกลาง-เล็ก หรือ REITs ที่ไม่มีคนเคาะซื้อขายบน Cboe จะทำให้แท่งเทียนหยุดนิ่งเหมือนระบบค้าง แม้ตลาด NYSE จะมีการเทรดปกติ
5. High/Low Wicks Incompleteness: WebSocket ส่งเฉพาะ Trade Event (Price, Volume) แต่ไม่ส่ง Day High/Low รวมของตลาด ทำให้ไส้เทียนของวันอาจเพี้ยน

## Resolution
เลือก Option A: จูน Polling ของ Yahoo บนชาร์ตหลักและ Watchlist เป็น 6 วินาที พร้อมหด Cache หลังบ้านเป็น 5 วินาที
- ได้ราคา Consolidated Tape แท้จริงจากทุกกระดาน
- ไส้เทียน High/Low ถูกต้อง 100%
- ราคาบนชาร์ตและ Watchlist ตรงกันเป๊ะทุกเซนต์
- ปลอดภัยจาก Rate Limit ไม่มีความเสี่ยงเรื่องกระดาน Cboe เงียบ
```
