# Reality-First Drift Detection Hotfix: Snapshot Injection (V2.6.1)

## 💡 Context & Implementation (Compiled Truth)

In V2.6.0, we overhauled the AI Portfolio Advisor to use a "Reality-First" dual-layer engine. Part of that overhaul was a new client-side drift detection system that compared the current UI state against the most recent `aiResult` to determine if a re-analysis was necessary.

**The Bug:**
The UI continued to incorrectly flag a "drift" even immediately after running a fresh analysis (the "วิเคราะห์ใหม่" button kept flashing). The drift note showed differences like `NVDA (27.1% -> 20%)`.

**The Root Cause:**
1. The drift logic in `AIBlueprintAdvisor.tsx` fell back to a legacy comparison method if `aiResult._requestSnapshot` was undefined.
2. The legacy comparison method mistakenly compared the user's `blueprints.target_percent` (e.g., 20%) against the AI's `aiResult.idealBlueprint.currentPercent` (which represented the user's ACTUAL holding percentage, e.g., 27.1%).
3. This mismatch guaranteed a false-positive drift every time.
4. `aiResult._requestSnapshot` was undefined because the Node backend on the VPS was never restarted after the V2.6.0 deployment, so it was running old code that didn't inject the snapshot into the DB.

**The Fix:**
1. **Frontend (`AIBlueprintAdvisor.tsx`):** Safely partitioned the drift detection logic. If `_requestSnapshot` is present, it compares `blueprints` against `snapshot.blueprints` and `holdings` against `snapshot.holdings`. If absent, it retains the legacy fallback.
2. **Backend (`server/routes/ai-advisor.js`):** Explicitly injected `_requestSnapshot` (containing `blueprints` and `holdings`) into the `parsedResult` before saving to SQLite.
3. **Deployment:** Pushed the compiled `dist/` and the updated `ai-advisor.js` to the VPS directly via SCP and executed `pm2 restart stock-api` to ensure the new code was loaded into memory.
