# X-Chart Trading Terminal, Multi-Tab Engine, S&P 500 Market Heatmap & Indicator Tuning (V2.13.0)

## 🧠 Context & Implementation (Compiled Truth)

### 1. ภาพรวมและเหตุผลในการพัฒนา (Core Architectural Purpose)
หลังจากที่ได้ติดตั้งเครื่องยนต์ TradingView Lightweight Charts (v5.2.1) ให้กับระบบ Project 2X ในเวอร์ชัน V2.12.0 ผู้ใช้มีความต้องการขยายขีดความสามารถขึ้นไปอีกระดับ โดยต้องการ **หน้าต่างเทรดดิ้งและวิเคราะห์กราฟเต็มจอเฉพาะกิจ (Dedicated Trading Terminal)** แยกออกจากหน้า Project 2X ภายใต้ชื่อ **"X-Chart"** ที่มีระบบ **Multi-Tab เหมือน TradingView** เพื่อรองรับ 3 มุมมองหลักในการสแกนตลาดพร้อมกัน:
1. **📈 Main Chart (หุ้นรายตัว):** กราฟเทคนิคอลหลัก ปรับแต่งสีและขนาดเส้น EMA 50/150/200 ตรงตามต้นแบบ 1:1 พร้อมแท่งเจ้ามือ Banker MCDX
2. **💱 กราฟค่าเงินบาท (USD/THB):** Ticker `THB=X` อัตราแลกเปลี่ยนดอลลาร์/บาทสด ย้อนหลัง 10 ปี เพื่อประเมินทิศทางกระแสเงินทุน (Capital Flow)
3. **🗺️ S&P 500 Market Heatmap:** แผนผังแผนที่ความร้อนของตลาดหุ้นสหรัฐฯ จัดหมวดตาม Sector เพื่อสแกนภาพรวมตลาดอย่างรวดเร็ว (Market Sentiment Scanner)

### 2. เจาะลึก 7 เสาหลักทางสถาปัตยกรรม (Deep Architectural Blueprint)

#### 2.1 EMA Ribbon & Banker MCDX Color Precision Tuning (1:1 Match)
ทำการเทียบภาพต้นแบบ TradingView ของผู้ใช้แบบ Pixel-by-Pixel และปรับจูนสีและขนาดเส้นใน `LWChart.tsx` และ `BankerMCDXPlugin.ts`:
- **EMA 50:** เปลี่ยนจาก `#38BDF8` (ฟ้าสว่าง 1px) เป็น **`#FFFFFF` (ขาวบริสุทธิ์) หนา 2px**
- **EMA 150:** เปลี่ยนจาก `#F59E0B` (ส้ม 1px) เป็น **`#2962FF` (Royal Blue) หนา 2px**
- **EMA 200:** เปลี่ยนจาก `#A855F7` (ม่วง 2px) เป็น **`#FFB300` (Amber Gold Core Bedrock) หนา 3px**
- **Banker MCDX Retail:** ปรับแท่งสีเขียวรายย่อยจาก `#22C55E` (Emerald สว่าง) เป็น **`#1B5E20` (Forest Green ป่าลึก)** สอดคล้องกับภาพต้นฉบับ
- **Crosshair Legend Bar Synchronized:** ปรับสีตัวอักษรของ EMA50 (`text-white`), EMA150 (`text-blue-500`), EMA200 (`text-amber-400`), และ Retail (`text-[#1B5E20]`) ให้ตรงกับสีเส้นจริงเพื่อความสบายตาและป้องกันการสับสน

#### 2.2 Wrapper Pattern Strategy (Zero Code Duplication)
เพื่อหลีกเลี่ยงการ Refactor ก้อนโค้ด `LWChart.tsx` (1,285 บรรทัด) ซึ่งผ่านการทดสอบ Live Pulse, Heikin-Ashi, Weekly, Envelope และ MCDX Plugin มาอย่างสมบูรณ์แล้วใน Project 2X จึงเลือกใช้ **Wrapper Pattern**:
- สร้าง `XChartPanel.tsx` ทำหน้าที่เป็น Consumer Shell:
  - รับ `symbol` และ `tabId`
  - ทำการ Self-Fetching ข้อมูล OHLCV และ Indicators จาก Backend ผ่าน `/api/chart/:symbol`
  - แปลงข้อมูลแล้วส่งต่อให้ `<LWChart {...props} />` โดย **ไม่ส่ง** Props ที่ผูกมัดกับ Project 2X เช่น `onAddInflow`, `scenario`, `trafficLight`, `watchlist`
- ผลลัพธ์: โค้ด `LWChart.tsx` ยังคงสะอาด 100% Project 2X ไม่ได้รับผลกระทบใดๆ (Zero Blast Radius) และ X-Chart ได้ใช้เครื่องยนต์ประสิทธิภาพสูงตัวเดียวกัน

#### 2.3 Zero-GPU-Memory-Leak Multi-Tab Engine (`xchartStore.ts`)
การเปิด Lightweight Charts Canvas หลายตัวพร้อมกัน (ตัวละ ~2-4 MB GPU Memory) อาจทำให้เบราว์เซอร์กระตุก:
- **Lazy Lifecycle Management:** แท็บที่ Active จะถูก Mount กราฟขึ้นมา ส่วนแท็บที่ไม่ได้เลือกจะ Unmount Component และทำลาย Canvas Instance ทิ้งทันที
- **State Persistence:** บันทึกแท็บที่เปิด, timeframe, chartStyle, และ activeTabId ลงใน `localStorage ('xchart_tabs_state_v1')` รีเฟรชหน้าเว็บแล้วแท็บและสถานะไม่สูญหาย
- **Quick Symbol Switcher:** คลิกเลือกหุ้นใน Watchlist Dock จะเปลี่ยน Symbol ของแท็บปัจจุบันทันทีโดยไม่ต้องเปิดแท็บใหม่ซ้ำซ้อน

#### 2.4 Self-Fetching Backend API (`server/routes/chart.js`)
สร้าง Endpoint อเนกประสงค์ที่ไม่ผูกติดกับ Portfolio ID:
- **`GET /api/chart/:symbol?days=3650`**:
  1. สั่งรัน `syncCandleDelta(symbol, days)` ดึง OHLCV และบันทึกลงตาราง `historical_prices` ใน SQLite
  2. คำนวณ `calcEMASeries` สำหรับ EMA 50, 150, 200 ทั้งชุดข้อมูล
  3. คำนวณ `calcMcdxSeries` (คำนวณบน 500 แท่งล่าสุดเพื่อความเร็ว แล้ว Zero-pad ส่วนหน้า)
  4. คืนค่า JSON ก้อนเดียวที่มี OHLCV, EMAs, Banker MCDX Series, ราคาล่าสุด และ % Change พร้อมเรนเดอร์ทันที
  5. รองรับทั้งหุ้นสหรัฐฯ (เช่น `VRT`, `NVDA`) และค่าเงิน Forex (เช่น `THB=X`)

#### 2.5 S&P 500 Mega-Cap Market Heatmap (`MarketHeatmap.tsx`)
- **Data Source:** จัดเก็บรายชื่อหุ้น S&P 500 Mega-Cap Top 50 ไว้ใน `server/data/sp500_top50.json` แยกตาม Sector ชัดเจน
- **Rate-Limit Guard 3 ชั้น:**
  - Layer 1: In-memory Cache TTL 60 วินาทีบน Server
  - Layer 2: Yahoo Bulk Quote ยิงคำขอเดียวรวดเดียว 50 หุ้น (วัดเวลาได้ 615ms สำหรับคำขอแรก และ 47ms เมื่อติด Cache)
  - Layer 3: Market Hours Cache Guard เมื่อตลาดปิด
- **Click-to-Chart Interaction:** คลิกกล่องหุ้นตัวใดก็ตามใน Heatmap ระบบจะเรียก `addTab({ type: 'STOCK', symbol })` เปิดแท็บดูกราฟของหุ้นตัวนั้นทันที

#### 2.6 Watchlist Dock & Macro Pin (`XChartWatchlistDock.tsx`)
- แถบด้านขวาขนาดกว้าง 320px ที่สามารถกดยุบ/ขยายได้ (Collapsible Dock)
- ปักหมุดอัตราแลกเปลี่ยน `USD/THB` (`THB=X`) Live ด้านบนสุด
- ดึงรายชื่อหุ้นใน Project 2X Watchlist พร้อมแสดงราคาล่าสุด, % Change วันนี้, สถานะ Traffic Light และ Banker Indicator
- ด้านล่างมี Active Focus Summary Card สรุปข้อมูลหุ้นที่กำลังโฟกัสอยู่

#### 2.7 App Routing & Layout Edge-to-Edge Optimization (`App.tsx` & `Sidebar.tsx`)
- เพิ่มเมนู `X-Chart` พร้อมไอคอน `CandlestickChart` ในกลุ่ม `strategy` ของ `Sidebar.tsx`
- เพิ่ม `'xchart'` เข้าใน `VALID_TABS` ของ `uiStore.ts` รองรับ URL Hash `#xchart`
- แก้ไขปัญหา Layout Padding ใน `App.tsx`: เมื่อ `activeTab === 'xchart'` จะปรับคลาสของ `<main>` เป็น `p-0 overflow-hidden flex flex-col` เพื่อให้กราฟขยายกว้างเต็มจอแบบ Edge-to-edge ส่วนหน้าอื่นๆ ยังคง `p-8 overflow-y-auto` ตามเดิม

### 3. มาตรฐานการปฏิบัติตามกฎเหล็ก (Iron Rules & UI Compliance)
- **Minimum Font Size Standard:** ข้อความทั้งหมดใน X-Chart มีขนาด >= 13px (`text-[13px]`, `text-sm`, `text-base`) โดยอนุญาตให้มีขนาด 12px (`text-xs`) เฉพาะ Badge Pills ขนาดเล็กเท่านั้น ไม่มีตัวหนังสือ 10px-11px หลงเหลือ
- **Perceptual Contrast Standard:** ความสว่างของตัวหนังสือบนพื้นหลัง Dark Mode สูงกว่า 70% (`text-slate-200`, `text-slate-300`, `text-amber-300`, `text-emerald-300`) ไม่ใช้สีเทามืดต่ำกว่า 50%
- **Zero Browser Subagent Testing:** ไม่มีการเปิดเบราว์เซอร์อัตโนมัติ ยืนยันความถูกต้องผ่าน `npx tsc --noEmit`, `npm run build`, และการยิง API ทดสอบบน VPS โดยตรง

## 2. Architecture: LWChart Extraction Strategy (ปมใหญ่สุด)

ปัญหาคือ `LWChart.tsx` **ผูกติดกับ Project 2X อย่างลึก** — มันรับ props 20+ ตัวจาก `Project2xPage` รวมถึง `onAddInflow`, `scenario`, `badge`, `trafficLight` ซึ่ง X-Chart ไม่ต้องการ

### ทางเลือกที่กูแนะนำ: **Wrapper Pattern (ไม่แตะ LWChart เลย)**

```
[ LWChart.tsx ]  ← คงไว้เป๊ะ ไม่แก้ไขโครงสร้าง (Project 2X ยังใช้อยู่)
      ↑
[ Project2xPage ] ← ส่ง props เดิมทั้งหมดเข้า LWChart

[ XChartPanel.tsx ] ← Component ใหม่สำหรับ X-Chart
      │
      ├── ดึง OHLCV จาก API `/api/chart/:symbol` เอง
      ├── แปลง response → LWChartProps
      └── เรนเดอร์ <LWChart {...mappedProps} /> โดยไม่ส่ง onAddInflow / scenario / badge
```

**ทำไมถึงเลือกทางนี้ ไม่ใช่ Custom Hook:**
1. `LWChart.tsx` ผ่าน Battle Test มาแล้ว (Live Pulse, Heikin-Ashi, Weekly, MCDX Plugin, Fullscreen) — ไม่อยากแตะของที่ทำงานอยู่แล้ว
2. Props ที่ X-Chart ไม่ต้องการ (`onAddInflow`, `badge`, `scenario`) มีค่า Default อยู่แล้ว ดังนั้นไม่ส่งก็ไม่พัง
3. ข้อเสียเดียวคือ Fullscreen Watchlist ของ LWChart จะแสดงถ้า `watchlist` prop ถูกส่ง — แต่ X-Chart มี Watchlist Dock ของตัวเอง จึง **ไม่ส่ง `watchlist` prop** ให้ LWChart ใน X-Chart context (Fullscreen watchlist จะไม่โผล่)

> [!TIP]
> **กฎเหล็ก: ไม่ Duplicate ไม่ Refactor — Wrap เท่านั้น** ทำให้ Project 2X ยังทำงานเป๊ะ และ X-Chart ได้เครื่องยนต์เดียวกัน

## 4. Multi-Tab Architecture: Canvas Lifecycle & State Persistence

### Tab State Shape (`xchartStore.ts`):

```typescript
interface XChartTab {
  id: string;                          // uuid
  type: 'STOCK' | 'CURRENCY' | 'HEATMAP';
  symbol?: string;                     // e.g. 'VRT', 'THB=X'
  title: string;                       // Display label
  // Per-tab viewport memory (restore on re-mount)
  viewState?: {
    timeframe: TimeFrame;
    chartStyle: ChartStyle;
    resolution: Resolution;
    showEnvelope: boolean;
    showSignals: boolean;
  };
}
```

### Canvas Lifecycle Strategy:

```
Tab A [VRT]  ← ACTIVE (Canvas mounted, live pulse running)
Tab B [NVDA] ← HIDDEN (Canvas destroyed, viewState saved in store)
Tab C [Heatmap] ← HIDDEN (Canvas destroyed, scroll position saved)

User clicks Tab B →
  1. Tab A: save viewState → destroy Canvas → unmount component
  2. Tab B: mount component → create Canvas → restore viewState → apply timeframe range
  3. Live Pulse timer moves from Tab A's symbol to Tab B's symbol
```

**ทำไมเลือก Destroy/Recreate แทน Hide:**
- Lightweight Charts v5.2 สร้าง Canvas ใน ~50ms (แทบไม่รู้สึก)
- ถ้าซ่อน 5 Canvas ไว้พร้อมกัน GPU memory จะพุ่ง 10-20 MB + Live Pulse timer วิ่ง 5 ตัวพร้อมกัน
- TradingView เองก็ใช้ strategy นี้ (สังเกตได้ว่าเมื่อสลับแท็บจะมี flash reload เล็กน้อย)
