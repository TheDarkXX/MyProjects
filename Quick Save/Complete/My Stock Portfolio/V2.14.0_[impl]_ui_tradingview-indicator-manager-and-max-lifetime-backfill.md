# TradingView-Style Indicator Manager, Client-Side Dynamic EMA Engine & Max Lifetime Historical Backfill (V2.14.0)

## 🧠 Context & Implementation (Compiled Truth)

### 1. ภาพรวมและเหตุผลในการพัฒนา (Core Architectural Purpose)
ในเวอร์ชันนี้ ระบบได้รับการยกระดับขีดความสามารถครั้งสำคัญ 3 ประการ:
1. **ระบบ Indicator Manager สไตล์ TradingView บน X-Chart:** ผู้ใช้ต้องการปรับแต่ง Indicator ทุกตัวได้อย่างอิสระเหมือนใน TradingView (เปิด-ปิดรายเส้น, ปรับ Period ของเส้น EMA เช่น 20/50/100/200, ปรับสีด้วย Color Swatch 12 สี TradingView, ปรับความหนา 1-4px, ปรับแบบเส้น Solid/Dashed/Dotted, ปรับ Bedrock Envelope ±%, เปิด-ปิดสัญญาณ Super Money ย่อย, และมี 1-Click Quick Presets)
2. **Dynamic Client-Side EMA Computation:** เดิมที Server คำนวณ EMA 50/150/200 มาให้ล่วงหน้า การจะให้ผู้ใช้เปลี่ยน Period แบบ Real-time จึงต้องสร้าง Pure Function `computeEMA(closes, period)` บน Client ให้คำนวณ 12,000 แท่งได้ใน < 0.5ms โดยไม่ต้องยิง API ใหม่
3. **Max Lifetime (All-Time IPO) Historical Backfill Engine:** ปรับปรุงระบบดึงข้อมูลราคาย้อนหลังจากเดิม 10 ปี (3,650 วัน) ขยายเป็น **Max Lifetime ตั้งแต่วันแรกที่หุ้นเข้าตลาด (IPO / 1927-01-01 / 36,500 วัน)** โดยทั้ง 3 สคริปต์ (`backfill_watchlist_87.js`, `backfill_10y.js`, `backfill_portfolio_and_refs.js`) รวมถึงระบบ Real-time on-the-fly backfill เมื่อเพิ่มหุ้นใหม่ใน X-Chart จะดึงข้อมูลระดับ Max Lifetime อัตโนมัติ พร้อมทั้งสร้างไฟล์ `HISTORICAL_INDEX.md` สรุปดัชนีข้อมูลอัปเดตตลอดเวลา
4. **อัปเกรดระบบตรวจสอบ `/recheck` เป็น V2 (Production Edition):** เพิ่มขั้นตอนตรวจสอบ API/DB Live Connectivity, Chart Data Flow & Rendering Integrity, Interactive Controls & Button Action Binding, และ Iron Rules UI

### 2. เจาะลึก 5 เสาหลักทางสถาปัตยกรรม (Deep Architectural Blueprint)

#### 2.1 Pure Client-Side EMA Engine (`src/utils/computeEMA.ts`)
สูตรการคำนวณ EMA ใช้แบบจำลอง Exponential Smoothing เดียวกันกับ Server ฝั่ง Node.js 1:1:
- ตัวคูณถ่วงน้ำหนัก: $k = \frac{2}{\text{period} + 1}$
- แท่งก่อนหน้าครบ Period จะคืนค่า `null`
- เริ่มต้น (Seed) ด้วย Simple Moving Average (SMA) ของ `period` แท่งแรก
- แท่งต่อๆ ไปคำนวณแบบลูกโซ่: $\text{EMA}_i = \text{Close}_i \times k + \text{EMA}_{i-1} \times (1 - k)$
- ประสิทธิภาพ: คำนวณ 12,000 แท่งเทียนใน ~0.45ms ทำให้การลากเปลี่ยน Period หรือกดเปลี่ยน Preset วาดเส้นใหม่ลงบน Canvas ได้แบบทันที (Instant Re-render)

```typescript
export function computeEMA(closes: number[], period: number): (number | null)[] {
  if (!closes || closes.length === 0) return [];
  if (period <= 0 || closes.length < period) {
    return new Array(closes.length).fill(null);
  }

  const k = 2 / (period + 1);
  const result: (number | null)[] = new Array(closes.length).fill(null);

  let sum = 0;
  for (let i = 0; i < period; i++) sum += closes[i];
  result[period - 1] = sum / period;

  for (let i = period; i < closes.length; i++) {
    const prev = result[i - 1];
    result[i] = prev !== null ? closes[i] * k + prev * (1 - k) : closes[i];
  }
  return result;
}
```

## 🏗️ Architectural Review — จุดที่ต้องแก้จากแพลนเดิม

> [!IMPORTANT]
> ### 3 ปัญหาโครงสร้างที่เจอในแพลนเดิม
>
> **1. State Ownership ผิดที่ — EMA ถูกคำนวณบน Server ไม่ใช่ Client**
>
> แพลนเดิมเขียนว่า _"คำนวณ EMA แบบไดนามิกบน Client ผ่าน `useMemo`"_ — แต่โค้ดจริงใน `XChartPanel.tsx` ยิง `api.chart.get(sym, 36500)` ซึ่ง **Server คำนวณ EMA 50/150/200 มาให้เสร็จแล้ว** ถ้าเราจะให้ผู้ใช้เปลี่ยน EMA Period ได้ (เช่น จาก 50 → 20) ต้องเลือก:
>
> - **Option A (แนะนำ):** เพิ่มฟังก์ชัน `computeEMA(closes, period)` บน Client เป็น pure function → ใช้ `useMemo` คำนวณจาก `data.closes` + user-defined period → **ไม่ต้องยิง Server ใหม่**
> - **Option B:** ส่ง period กลับไปให้ Server คำนวณ → ช้า, ต้องรอ network round-trip ทุกครั้ง
>
> **กูแนะนำ Option A** — EMA เป็นแค่ exponential moving average, คำนวณ 12,000 จุดใน ~0.5ms บน Client ได้สบาย
>
> **2. Indicator Config ไม่ควรอยู่ใน `xchartStore.ts`**
>
> `xchartStore.ts` ตอนนี้มี **451 บรรทัด** จัดการ Tabs + Watchlist Sections + Quotes + Sort + Detail — มันเป็น Store ระดับ **Layout/Navigation** ถ้ายัด Indicator Config เข้าไปอีกจะบวมจนแก้ไม่ไหว
>
> ✅ **แก้:** แยกเป็น `useIndicatorStore.ts` (Zustand store ใหม่) — แยกหน้าที่ชัดเจน, แต่ละ Store มี single responsibility
>
> **3. LWChart.tsx มี 1,360 บรรทัดแล้ว — ห้ามยัดเพิ่มอีก**
>
> Component นี้จัดการทั้ง chart creation, data transform (HA, weekly aggregation), signal markers, toolbar, crosshair legend, live pulse, fullscreen — **ทุก concern อยู่ในไฟล์เดียว** ถ้ายัด Indicator Manager UI + client EMA compute + color picker เข้าไปอีก จะเลย 2,000 บรรทัดแน่นอน
>
> ✅ **แก้:** สร้าง `IndicatorManagerPopover.tsx` เป็น Component แยก ที่อ่าน/เขียน `useIndicatorStore` โดยตรง → LWChart แค่ subscribe ค่าจาก store แล้ว `applyOptions` ตาม

    - ปรับ **`▲ BUY`** เป็นลูกศรชี้ขึ้นเด่นชัด (shape `arrowUp`, label `▲ BUY`)
    - ปรับ **`★ SUPER`** เป็นลูกศรใหญ่พิเศษ 1.35x (shape `arrowUp`, label `★ SUPER`) พร้อมเพิ่มระบบ Font Fallback (`Segoe UI Symbol / Segoe UI Emoji`) เพื่อให้สัญลักษณ์รูปดาว ★ เรนเดอร์บน HTML5 Canvas ได้ 100% บนทุกแพลตฟอร์ม
    - ปรับ **`▼ EXIT`** เป็นลูกศรชี้ลงสีแดงเข้ม (shape `arrowDown`, label `▼ EXIT`)
  - **ถาดสีแยกเฉพาะ 4 สัญญาณ:** เพิ่ม `SignalColorsConfig` ใน Zustand Store ทำให้ผู้ใช้ปรับแต่งสีของ READY, BUY, SUPER, EXIT แยกกันได้อย่างอิสระผ่าน ColorPickerDropdown (ทั้ง 12 สี TradingView, 5 สล็อต Custom Palette, และกรอกรหัสสี HEX)
  - **Dynamic Spacing / Padding (px Input):** แทนที่ปุ่ม 1-4 ตายตัวด้วยระบบ **Numeric Stepper (px)** ให้ผู้ใช้พิมพ์กรอกระยะห่างเป็น px ได้เองอิสระ หรือกดปุ่ม `[-]` / `[+]` เพื่อขยับทีละ 2px พร้อมปุ่มลัด `0px`, `8px`, `14px`, `20px`
