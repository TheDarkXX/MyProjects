# V2.40.0: TWR Institutional Standard, Reload Flash Fix & Stale-While-Revalidate Architecture

## 📌 Context & Implementation (Compiled Truth)

1. **Transaction Ingestion**: User provided 4 screenshots from Tiger Trade (`Discord_*.jpg`) for recent portfolio activity in September 2026. Non-duplicate items needed to be identified, recorded, and verified against SQLite `stock.db` on local and VPS live environments.
2. **Withdrawal Dilution Query**: After withdrawing $850.08 USD, the simple return percentage spiked from +35% to +215% because withdrawing capital shrank the denominator (`netInvested = $610.30` while `totalPnl = +$1,315.39`). User inquired if this was correct and instructed:
   > "งันก็ twr แบบสากล ให้ตรงกันได้ดลย บังคับใช้ TWR เป็นค่า Default ของพอร์ตเสมอ เช่นกัน"
3. **Bug 1 (37,000,000% Flash on Refresh)**: Upon initial page refresh, the dashboard cards briefly flashed absurd values like `TOTAL RETURN: +-37,297,306.70%` and `YTD: +667,802,037.96%`.
4. **Bug 2 (19.76% Flash on Refresh)**: After guarding against dust division, on page refresh the cards still briefly flashed `TOTAL RETURN: +19.76%` with `1D, 1W, 1M, YTD: $0.00 (+0.00%)` for ~500ms before snapping to the true TWR.

### 2. Architectural Root Cause Analysis

#### A. The 37,000,000% Dust Division Anomaly
- In `Dashboard.tsx`, `allDailyPoints` iterated over dates gathered from `allPortfolioSymbols`.
- When SPY historical data arrived from cache/network before individual stock quotes (`NVDA`, `TSLA`, `CRWD`, etc.), `dailyStockValue` was computed as `0`.
- Portfolio NAV for each day collapsed to only residual cash dust (`dailyCash = $0.05` or `$4.89`).
- In the daily TWR compounding equation:
  $$\text{dayReturn} = \frac{\text{NAV}_{\text{today}} - \text{CashFlow} - \text{NAV}_{\text{yesterday}}}{\text{NAV}_{\text{yesterday}}}$$
  When $\text{NAV}_{\text{yesterday}} \approx 0.05$ and stock quotes arrived or deposits settled, $\text{dayReturn}$ skyrocketed by $370,000\times$.
- Compounding this over hundreds of trading days produced `+-37,297,306.70%`.
- Furthermore, `MultiPeriodReturnStrip.tsx` checked `isPositive = metric.amount >= 0` (which was positive `+$734.18`) and prepended `+` to the string of a negative percent, creating `+-37297306.70%` and a green up-arrow for a negative number.

#### B. The 19.76% Fallback Flash
- In `useHoldings.ts`:
  - `totalNetWorth = $1,344.48`
  - `netInvested = $610.30`
  - `totalPnl = $734.18`
  - `grossInvested = $3,715.49`
  - Simple return on gross invested capital: $\frac{734.18}{3715.49} \times 100 = 19.76\%$.
- `usePriceStore` and `useTransactionStore` were initialized in-memory with `{}` and `[]`.
- Every page refresh cleared all memory. For 500–1000ms while waiting for Yahoo Finance API:
  - `hasStockHistorical` was `false`.
  - `Dashboard.tsx` safely fell back to `totalPnlPercent` ($19.76\%$) for `ALL`, and `$0.00 (+0.00\%)` for other timeframes.
- Once the API responded, TWR was calculated and replaced $19.76\%$ with the true TWR, creating a visible visual flash.

### 3. Comprehensive Solutions Implemented

#### Solution 1: Database Migration & Cash Balance Reconciliation
- Created `server/scripts/apply_september_withdraw_and_fees.js`.
- Updated RBRK sell fee to $0.02 (SEC fee) and META sell fee to $0.01 (TAF fee) on 2026-09-17.
- Recorded $850.08 USD exchange withdrawal on 2026-09-17.
- Reconciled cash balance to exact $4.89 USD.
- Executed and validated on local SQLite and live production VPS (`185.250.38.247:/root/stock-portfolio/server/db/stock.db`).

#### Solution 2: TWR Institutional Standard & Gross Capital Anchor
- Updated `src/hooks/useHoldings.ts`: When cash withdrawals cause `netInvested` to fall below 50% of cumulative deposits, anchored simple return to `grossInvested` ($3,715.49) to eliminate denominator collapse.
- Implemented daily Time-Weighted Return (TWR) across `allDailyPoints` in `Dashboard.tsx` and `MobileDashboard.tsx`, neutralizing the distortion of cash withdrawals.

#### Solution 3: TWR Numerical Stability & UI Decoupling
- **NAV Floor & Anomaly Filter**:
  - Required $\text{prevVal} \ge \$10.00$ before calculating daily percentage changes (eliminates division by cash dust).
  - Enforced single-day return filter: $\text{dayReturn} > -0.99 \text{ and } < 3.0$ (rejects impossible $>300\%$ single-day jumps from missing price bars).
- **Price Fallback Baseline**:
  - Implemented fallbacks in `allDailyPoints`: `point.price` $\rightarrow$ `prices[symbol]?.price` $\rightarrow$ `tx.price` (cost basis).
  - Lookback buffer: Subtracted 14 days from `earliestTxDate` so historical prices start before the first trade.
- **UI Decoupling**:
  - Separated `isAmountPositive = metric.amount >= 0` from `isPercentPositive = metric.percent >= 0` in `MultiPeriodReturnStrip.tsx` and `PortfolioHero.tsx`.
  - Arrow direction, text color, and `+` prefix are 100% synchronized with the percentage sign, eliminating `+-` permanently.

#### Solution 4: Optimistic Stale-While-Revalidate (SWR) Caching
- **Persistent Price Store (`src/stores/priceStore.ts`)**:
  - Cached `prices`, `historical`, and `exchangeRate` in `localStorage`.
  - On app mount/refresh, initializes state directly from `localStorage` at 0ms.
- **Pre-hydrated Transactions (`src/stores/transactionStore.ts`)**:
  - Cached transaction records per portfolio in `localStorage`.
  - On `fetchTransactions`, immediately hydrates from cache before network request fires.
- **Period Metrics & TWR Snapshot (`src/components/dashboard/Dashboard.tsx` & `src/views/mobile/MobileDashboard.tsx`)**:
  - Cached computed period metrics (`1D`, `1W`, `1M`, `3M`, `YTD`, `1Y`, `ALL`) in `localStorage`.
  - If historical data is refreshing, immediately serves the cached TWR snapshot.
  - Eliminated the fallback to `19.76%`, completely preventing visual flicker on reload.
