# DrView Extension Rendering Fixes (TSV & Mermaid v11)

## 📌 Context (Compiled Truth)
The DrView VS Code Markdown viewer experienced bugs where interactive elements (Mermaid diagrams and TSV spreadsheet tables) failed to render and instead displayed as raw `<pre><code>` blocks. 

1. **The Code Block Enhancer Race Condition**: 
   The `enhanceCodeBlocks()` function (which adds the "📋 Copy" button and language badges) was executing *before* the TSV and Mermaid renderers. Because it didn't properly skip them, it wrapped their native `<pre><code>` structures in a `.code-block-wrapper` div. This mutated the DOM structure, causing the specialized renderers to fail to identify their target elements.

2. **The Mermaid ES Module Global Scope Bug (v11.16.1)**:
   Mermaid v11 has shifted to ES Modules. The bundled `mermaid.min.js` uses an esbuild wrapper (`__esbuild_esm_mermaid_nm`). The script attempted to expose itself to `globalThis["mermaid"]`, but in the strict Sandboxed Webview context of VS Code, `var` declarations in scripts don't naturally map to `globalThis` if executed a certain way. This resulted in `typeof mermaid === 'undefined'` evaluating to `true`, completely skipping the rendering pipeline and leaving the raw code block.

**Solution Implemented**:
- Adjusted the execution pipeline in `initViewer()` to execute `renderMermaidDiagrams()` and `renderTsvSpreadsheets()` **first**, wrapping each securely in `try/catch` blocks.
- Implemented a custom object extraction fallback in `renderMermaidDiagrams()`: if `window.mermaid` is undefined, it actively pulls the default export from `__esbuild_esm_mermaid_nm.mermaid.default`.
- Optimized the Top Header Bar: Removed the redundant secondary file-path row to maximize vertical screen space, relocating UI controls (Outline, Font-size, Focus) directly to the main toolbar alongside a new **Code** button that opens the raw markdown source natively.
- Eliminated brittle Regex-based Mermaid diagram converters, implementing 7 dynamic CSS theme classes (Dark, Cyberpunk, Dracula, etc.) manipulating the `.mermaid-viewport[data-theme]` root.

## 🔬 Timeline & Debugging Log
- **Observation**: User reported that `tsv` and `mermaid` blocks were not rendering, presenting as raw markdown syntax.
- **Action**: Identified that `enhanceCodeBlocks` was wrapping all blocks without exclusions. Added explicit `if (lang === 'MERMAID' || lang === 'TSV') return;` but it still failed.
- **Observation**: Discovered that execution order in `initViewer` allowed code block wrappers to execute first. Swapped execution order.
- **Verification**: TSV began rendering successfully. However, Mermaid continued failing, eventually displaying a literal "Syntax error in text" before reverting back to plain text entirely.
- **Deep Dive (Mermaid)**: Investigated the `mermaid.min.js` file included in the extension. Discovered it was v11.16.1 built via esbuild. The `typeof mermaid === 'undefined'` guard in `viewer.js` was triggering because the script's attempt to attach to `globalThis` was silently throwing an exception and halting execution due to scope restrictions.
- **Final Fix**: Injected an extraction bypass `window.mermaid = __esbuild_esm_mermaid_nm.mermaid.default` ensuring the global reference is successfully created prior to `mermaid.render()`.
- **Packaging**: Built final `drview-1.3.4.vsix` via `vsce package` for immediate client installation.
